## 重做多图合成版式（用户反馈：两张素材叠在同一画面看起来脏）

**需求**：去掉"同一画面两个素材叠加"的多图组合方式，换成别的组合方式，并多开发几种。

### 删掉的两个版式
- `double_exposure`：两张满屏图 `blend=all_mode=screen` 混合，纯叠加。
- `photo_stack`：卡片压在另一张满屏底图上，卡片之间也互相重叠。

### 新增的 4 个版式（全部互不重叠）
| 版式 | 张数 | 做法 |
| --- | --- | --- |
| `hero_split` | 2 | 2:1 主副竖分栏 |
| `diagonal_split` | 2 | 半分辨率 geq 蒙版做硬边斜切，四种斜向按 `shot.index` 轮换 |
| `triptych` | 3 | 三联竖排 |
| `hero_grid` | 3 | 左 2/3 大图 + 右侧上下两块 |

保留 `split_screen`（等宽双栏）和 `beat_montage`（一次只显示一张，唯一有意保留留边）。
词表落在 `planner.IMAGE_COMPOSITES`（name -> 设计张数, 最少张数），`_COMPOSITE_SMALLER`
给出容量不够时的降级链（triptych/hero_grid -> 两栏）。

### 顺手修掉的两个真 bug
1. **门控计数器自我强化，`image_composite_ratio` 完全失效**：门控和运镜轮转共用
   "已选出的单图镜头数"，而该计数器只在门控**拒绝**时前进 —— 一个镜头变成多图就把
   决定它的计数器冻住。实测 0.24 / 0.5 / 1.0 三个比例输出完全一样，**每个图片镜头都是
   多图合成**。现在门控和版式轮转都按镜头序号 `index` 推进，运镜轮转才用单图计数。
2. **分割缝隙从宽度里挖出来**：各格宽度之和比画布少几个像素，最后归一化把镜头放大再用
   黑边补齐 —— 每个分屏镜头左右各一条黑边。现在缝隙是画在接缝**之上**的半透明发丝线，
   各格宽度之和恰好等于画布。格宽也不再为缝隙预留（否则 1920 上三联是 634/634/652）。

## 用户反馈"貌似没有用到字体，实际渲染的时候"——查出三个真缺陷

用**像素**而不是读配置来判定：同一条歌词在不同预设/字重下渲染，比较墨量。三个缺陷都会渲染出
一帧完全合法但字体不对的画面，所以读代码看不出来。

1. **自带字体对 libass 完全不可见。** `subtitle_fonts_dir = "fonts"` 相对**项目目录**解析
   （`config.py` 的 `resolve_paths`），于是 `my-mv/fonts`（`init` 建的空目录）和 `demo/fonts`
   （不存在）都指向空处，`fontsdir` 要么没传要么指向空目录 → libass 只看得到系统字体。
   实测 `Ma Shan Zheng` 有 fontsdir 时墨量 3785、无时 6389（回退到别的 face）。
2. **预设候选可能解析出一个不存在的家族名。** 模糊匹配 `installed in key` 让 `Kaiti SC`
   命中系统里的 `KaiTi`，但写进 ASS 的却是候选名 `Kaiti SC` → libass 找不到 → **静默回退**。
   "名字不存在"和"字体找不到"在屏幕上一模一样。
3. **可变字体的字重完全不生效，而且默认实例是细体。** `fonts/NotoSansSC-VF.ttf` 的 fvar
   是 `wght 100..900`、**默认 100（Thin）**，`NotoSerifSC-VF.ttf` 默认 200（ExtraLight）。
   libass（Windows/DirectWrite）不会应用 `wght` 轴：它向提供方要 700 的 face，拿回默认实例，
   而看到家族"已经有 Bold"就不再合成粗体 → `\b300/400/700` 逐像素相同（实测三档墨量都是
   3615）。这也是用户成片里字幕是发丝细体的原因。

### 修法
- `fonts.py` 新增 `PACKAGED_FONTS_DIR` 与 `font_directories()`：**仓库自带的字体永远在搜索
  路径里**，项目目录只是额外一层。
- `stage_fonts()`：把两者收集进**一个**目录（libass 的 `fontsdir` 只接受一个——传两个路径
  无论用 `;` 还是 `:` 都一个字体都找不到），并用 fontTools 把可变字体**烘成静态字重**
  （Light/Regular/Bold，改 name 表族名 + `OS/2.usWeightClass` + `fsSelection`/`macStyle`，
  保留版权与 OFL 记录）。
- 缓存放在**整机级别**（`%LOCALAPPDATA%\beatforge\fonts\<摘要>`，可用
  `BEATFORGE_FONT_CACHE` 覆盖），不放项目 `.beatforge/`：烘 6 个 CJK 实例约 70 秒，
  只取决于字体本身。缓存键 = 目标名 + 源文件名 + 大小 + mtime + 字重。
- `resolve_subtitle_font` 模糊命中时返回**实际存在的那个拼写**；显式家族名也走 `_parse_entry`，
  于是 `subtitle_font = "Noto Sans SC@500"` 不再是静默回退。
- `write_ass` 的 Style Bold 跟着解析出的字重走（≥600 才 `-1`），不再无条件粗体。
- 性能：`_table_bytes()` 只读需要的表（原来为解析几 KB 的表把 17 MiB 的字体整个读进来，
  每次 render 要读几百 MB）；实测测试套件冷启动 488s → 105s，热启动 36s（基线 34s）。
- `scripts/font_probe.py`：逐预设量墨量 + 同家族三档字重对比 + 有/无 fontsdir 对比。
- 新增 12 条测试（378 passed），关键是
  `test_a_requested_weight_actually_reaches_the_rendered_frame`（三档字重墨量必须递增）。
- fonttools 已加进 `pyproject.toml` 主依赖（`uv lock` 无需下载，本来就在锁里）。
- 前后对照（用用户自己的 `my-mv/.beatforge/lyrics.ass` + `picture.mp4`）：同一帧文字覆盖
  像素 3040 → 3843，明显从细体变成 ASS 要求的粗体。见 `.probe/font-compare/before-after.png`。
