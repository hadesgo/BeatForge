# 渲染产物时间轴验证

**核心原则：渲染成功 ≠ 画面正确。** 命令返回 0、文件存在、时长看起来合理，都不能说明镜头落在
该落的位置上。必须**测量产物**，不能相信日志。

## 何时必须做

- 改了任何影响时序的代码：转场、`_render_shot` 的时长、拼接、`trim`、帧率。
- 改了运镜几何（`perspective` 四边形、zoom/滚转/梯形/手持）。
- 用户报"渲染崩了"并已修复——**修完要验证的不只是不崩，而是产物正确**。
- 任何"修好一个 bug 后重跑"的时刻：后一个 bug 常常只在前一个修好后才会暴露。

## 不变量（先算出来，再验证）

把方案（`plan.json` 之类）当作**权威时间轴**：`shots[i].start` 是每镜必须开始的位置，
`Σ duration` 是成片应有的总长。然后：

```python
plan_total = sum(s["duration"] for s in shots)     # 应有总长
```

成片时长必须与它一致（相差 ≤ 1 帧）；逐切点位置必须**不累积漂移**。

## 四个测量手段（按代价从低到高）

### 1. 总长比对（秒级，先做这个）
```bash
ffprobe -v error -show_entries format=duration -of default=noprint_wrappers=1:nokey=1 out.mp4
```
与 `plan_total`、与音轨时长比。**差值为正且大于 1 帧 → 后面必然有累积漂移**；
被 `-shortest` 截掉的话，成片会等于音轨长度，而中间产物（拼接后的无声画面）更长——
两者不一致就是截断的信号。

### 2. 逐切点偏差（一次 ffmpeg 调用，扫全片）
用场景分找出真实切点，与方案切点比：
```bash
ffmpeg -i picture.mp4 -vf "select='gte(scene,0)',metadata=print" -f null -
```
- `pts_time` 与 `lavfi.scene_score` **分行输出**，正则要跨行配对（逐行记 `pts_time`，
  下一行的 `scene_score` 配给它）。
- 在每个方案切点 ±0.2s 窗口内取场景分峰值，得真实切点。
- **看趋势，不看单点**：偏差随时间单调增大 = 累积漂移（真 bug）；散布在 0 附近 = 正常。
- 阈值取 0.05 以上才算可信峰值；溶解/相似画面的切点检测不到，属正常，别据此下结论。

### 3. 逐镜头对齐（中等代价，用于定位到具体镜头）
把某个镜头的**剪辑文件**中点帧与成片中该镜头方案中点帧逐像素比。
注意两点系统性偏差，否则会误判：
- 剪辑长度是 `D + 入场重叠`，所以剪辑中点对应成片的 `start + D/2 - s_in/2`，**不是** `start + D/2`。
- 片尾有刻意的 `fade=t=out`，最后 0.5s 帧差必然很大。

### 4. 离线模拟时间轴代数（几秒钟，**在花十几分钟重渲染之前做**）
把拼接的时间轴算法用 Python 重写一遍（用实测的剪辑时长），预测最终时长与 clamp 次数。
本方法预测 197.563s、实跑 197.567s。**先预测再跑**，避免白等一整轮渲染。

## 已知会出问题的三类（都实测过）

1. **补错了重叠的侧**：滤镜链是 `x_k = xfade(x_{k-1}, clip_k)`，混合段展示**第二个输入**的第 0 帧起，
   所以每镜时长必须是 `D + 入场重叠`，不是 `+ 出场重叠`。补错侧 → slack 放在没人消费的一端，
   累积流比方案长，`-shortest` 从片尾悄悄切掉（实测末镜丢 33%）。
2. **帧取整累积**：剪辑是整数帧而 `trim=duration=` **向上取整**，每镜最多长一帧；
   253 镜累加 = +0.578s。修法是把每个转场锚定到方案位置（`min(方案位置, 实测流上限)`），
   而不是跟着实测时长累加。
3. **Windows 命令行上限 32767**：把全部镜头当 `-i` 一次性喂给 ffmpeg 时，滤镜图 + 路径会超限，
   抛 `FileNotFoundError: [WinError 206]`。**所有镜头都渲染成功后才在拼接时炸**，
   症状是最终文件不存在、中间文件还是上一次的。滤镜图要写进文件用 `-/filter_complex <文件>`。

## 几何回归（改运镜时）

- 逐帧求值四边形，**扫 `amount`（每镜强度）的整个区间**，不能只测一个点——
  "乘不乘 `amount`"在 `amount == 1` 时完全等价，单点测试天然漏掉这类 bug。
- 只有带滚转/梯形的运镜才可能越界：轴对齐四边形的包围盒就等于裁剪框。
- 判据用**最紧余量**（负值即越界像素数），比"是否越界"更能看出逼近程度。
- 本仓库现成工具：`scripts/quad_probe.py`、`scripts/jitter_probe.py`、
  `tests/test_renderer.py` 里的 `stays_in_frame_at_every_camera_intensity`。

## 报告纪律

- 给出**前后对比的数值**（总长、末镜实播时长、偏差趋势），不要只说"修好了"。
- 区分"测量噪声"与"真偏差"：测量方法本身有 1–2 帧的粒度，别把噪声当 bug 继续追。
- 残留的已知偏差要**明说并给出量级**（例如"残留 −0.06s，来自 trim 帧粒度，低于可感知阈值"）。
