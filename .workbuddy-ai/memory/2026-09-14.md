## 图片运镜抖动（晚上）
- 现象：带缩放动效的镜头（用户举例 `demo/.beatforge/clips/00002.mp4`）画面有规律性顿挫。
- 根因：`renderer.py::_image_filter_graph` 用 `zoompan`，其 `x`/`y` 会被**截断到输入帧的整数像素**。
  本项目运镜速度只有 0.03–0.1 px/帧，于是图像连续多帧完全静止、再突然跳 1 个整像素，
  在直线边缘上肉眼可见。
- 修复：改用 `perspective`（`interpolation=cubic:sense=source:eval=frame`），逐帧求值裁剪四边形，
  真正的亚像素仿射重采样，且只重采样一次。
  - 关键坑 1：`perspective` 的表达式**只暴露 `on`（帧序号），不暴露 `t`**；用 `t` 会报
    `Undefined constant or missing '('`。
  - 关键坑 2：裁剪框宽度是 `W/zoom`，可平移量程是 `W - W/zoom`，两者极易写反；
    写反会变成 19 倍硬推镜（曾一度踩到，靠受控探针输出全平帧定位）。
- 量化效果（受控探针 `camera_move_probe.py --controlled`，即真实渲染路径但关掉暗角/颗粒/调色）：
  旧 zoompan 抖动 1.67px、抖动/单帧步长比 18.6 → 新 perspective 0.117px、比值 1.5。
  受控卡 A/B（`filter_ab.py`，1280×720，zoom 1.07）：zoompan 104/119 帧完全静止、抖动 0.98px、
  抖动/步长 7.4；perspective 0 静止帧、抖动 0.00px。
  更直接的证据（不依赖任何位移测量）：受控卡上 zoompan 的相邻帧最大像素差 min 0.00 / max 131
  （连续多帧完全相同再猛跳），perspective 是 min 20 / max 21（每帧均匀变化）。
  另用穷举匹配反解每帧真实裁剪原点，确认 perspective 的 origin 以 0.12–0.14px/帧平滑推进。
- **测量方法本身踩过的坑（重要）**：
  1. 相位相关只在相邻帧互为**刚体变换**时有效。成片里的暗角、颗粒、调色固定在画面坐标上，
     会破坏这一前提，导致单帧步长正负相消、读数全是噪声。真实片段 `00002.mp4` 上
     `jitter_probe.py` 曾报出 58/101 静止帧 + 1.75px 抖动，其实一致性只有 0.033，全是噪声。
     两个探针现已加入一致性判据（`|Σstep| / Σ|step|`，< 0.5 直接判定"测量不可信"并拒绝结论）。
     **不要再拿成片直接测运镜抖动**，要用 `camera_move_probe.py --controlled`。
  2. float32 输入会让 FFT 静默退化成 complex64；两帧都是中灰导致互功率谱 DC 极大，
     `ifftn` 出的相关面基底比真实峰高约 1e4 倍，complex64 下峰被舍入噪声淹没，
     整型峰恒落在 (0,0)。必须去均值 + 转 float64。
  3. 用三点抛物线拟合峰值在小平移下有约 40% 低偏差（真实 0.13px 读成 0.08px），
     而这正是运镜所处的量级。改用局部上采样 DFT（`_upsampled_dft`）后误差 < 0.01px。
  4. 测试卡不能用平滑噪声（相关面没有高频，量化噪声反超真实信号），也不能用条纹/棋盘
     （周期假峰）；要用类照片的 1/f（粉红）噪声，且保持中灰（渲染器的 `eq=brightness=-.025`
     会把近黑背景压成 0，测量动态范围归零）。

## 动效与转场扩充（傍晚）

- **转场**：6 种 → 14 族 / 39 个具体 `xfade`（`_TRANSITION_LIBRARY`）。
  规划器只下发**族**（`_transition_family`，按情绪/段落/能量/冲击点决定），
  `_transition_spec` 再结合**进入镜头的 `transition_tone`** 与**离开镜头的漂移方向**解析成具体名。
  `dip`/`flash` 由色调定色（淡黑=沉重，淡白=释放），方向性族（wipe/slide/diag/reveal/slice）
  跟随镜头自身漂移方向。新增 `_TRANSITION_PACE` 逐族时长（flash 0.16s … dissolve 0.44s）。
  未知族名回退成溶解而不是硬切。新增 `render.transition_density`（默认 0.35）控制段落内部可见转场比例；
  段落切换/乐段边界/导演冲击点不受该比例约束。`_break_transition_repeats` 防止同一族连续出现
  （`cut`/`dissolve`/`blur` 这类含蓄转场除外）。
- **单图运镜**：实质 3 种 → 12 种（`_CAMERA_MOVES`，参数化 `_CameraMove` 冻结 dataclass）。
  按"性格"分类：铺垫（cinematic_depth/focus_pull）、揭示（pan_reveal/tilt_up/tilt_down/arc/drift）、
  承诺（dolly_in/dolly_out/punch_in/pull_back）、呼吸（breathe）。
  `zoom_from`/`zoom_to` 是**增量倍率**，`x_from..y_to` 是**平移量程的比例**（±0.15 以内）。
  新增 `_EASES`（linear/out/in/inout）。全部走 `perspective` 亚像素路径，不退回 zoompan。
- **三种复合动效**：`film_bars`（drawbox 叠 2.35:1 遮幅）、`iris`（圆形遮罩）、
  `parallax`（模糊背景 + 清晰前景双平面异速平移）。`_adapt_image_layers` 从 `_adapt_image` 拆出，
  让 parallax 能在合成前分别移动两个平面。
- 规划器：`_single_image_effect`（按 edit_intent/段落/能量/旋律固定轮转，不用随机数）、
  `_framing_effect`（约 1/12 概率给 iris/parallax/film_bars）。

### 这一轮踩到并修掉的三个 ffmpeg 坑（都很隐蔽，详见 MEMORY.md）
1. **`perspective` 的 `on` 是 1-based**（`vf_perspective.c`: `VAR_ON = outl->frame_count_in + 1`），
   且会**越过镜头长度继续增长**（静态图来自 `-loop 1` 无限长，下游 `fps`/`trim` 会多拉几帧）。
   进度必须写成 `clip((on-1)/(frames-1),0,1)`：少偏移 → 末帧过冲；少钳制 → 递减型运镜在末尾反转，
   zoom 掉到 1 以下 → `W-W/zoom` 变负 → 该帧被拒。
   症状极具误导性：只有 `dolly_out`/`pull_back`/`breathe` 崩，`cinematic_depth` 这类递增运镜全正常。
2. **ffmpeg 的 `clip()` 不交换上下界**：算的是 `min(max(x,min),max)`，上界为负就原样返回负数。
   `clip(5,0,-1)` 实测直接 EINVAL。因此另加了 `_MIN_ZOOM = 0.004` 抬高放大率，消除"裁剪框=整帧"的退化映射。
3. **`geq` 没有 `on` 变量**，它用 0 基的 `N`（`perspective` 用 1 基的 `on`，两套方言）。
   另外 `geq` 是逐像素求值，1080p 实测 0.18s/帧（约 5.5fps），比其它效果加起来还贵；
   iris 改为在 1/8 画布上生成遮罩再 `scale` 上采样（顺带得到更柔的边缘）。
4. **合成平面会被 `shortest=1` 截短整镜一帧**（`_plane_duration` = duration + 1/fps）。
   这同时暴露了一个**既有 bug**：`split_screen` 一直在丢最后一帧。
